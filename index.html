How I work

A product goes through six stages with me, from the first workshop to the release after the release. Every stage ends with something you can see and test.

1/ 6

  1. 1

    Discover

    I start with the business goal, the users and the technical constraints. Workshops with stakeholders turn a rough idea into a prioritised scope.

    You getScope, user stories and an estimate

  2. 2

    Design

    User flows, wireframes and high-fidelity screens in Figma, following Apple's Human Interface Guidelines. I prototype the risky interactions before any code is written.

    You getFlows, UI design and a clickable prototype

  3. 3

    Architect

    I choose the architecture, module boundaries and data layer to fit the product's lifespan, and agree API contracts with the back-end team early.

    You getArchitecture plan, API contracts and a CI pipeline

  4. 4

    Build

    SwiftUI or UIKit in small, reviewable pull requests. Modern concurrency, dependency injection and feature flags keep the codebase easy to change.

    You getA working build at the end of every sprint

  5. 5

    Test

    Unit and UI tests run on every commit. I profile with Instruments and check accessibility, localisation and offline behaviour on real devices.

    You getAutomated tests, performance and accessibility checks

  6. 6

    Ship and improve

    TestFlight betas, phased App Store releases and crash monitoring. After launch, analytics and user feedback decide what gets built next.

    You getApp Store release, monitoring and a roadmap
